# Desktop-приложение asledger

Desktop-клиент на Electron запускает локальный `asledgerd`, показывает его
состояние и открывает книгу в отдельном окне. Android-клиент и Go-сервер при
этом не меняются: desktop — ещё один способ запустить тот же сервер.

## Поддерживаемые платформы

| Платформа | Артефакт | Статус в `v1.3.0` |
| --- | --- | --- |
| Linux x86_64 | AppImage, deb | поддерживается |
| Linux arm64 | AppImage, deb | поддерживается |
| Windows 10/11 x64 | NSIS, portable, ZIP | поддерживается, без подписи |
| macOS | — | не входит в MVP: нет сертификата и нотаризации |

Установка AppImage, portable и ZIP не требует прав администратора. deb и NSIS
могут ставить приложение в системный или пользовательский каталог; для работы
без администратора используйте AppImage/portable/ZIP. Windows-артефакты не
подписаны, поэтому SmartScreen может показать предупреждение.

## Архитектура

```
Electron main
├── config.json / userData      порты, пути к данным и журналам
├── BackendProcess              spawn asledgerd, healthcheck, SIGTERM
├── NetworkMonitor              локальные IPv4 и URL для телефона
└── BrowserWindow
    ├── окно управления         статус, журнал, адреса, кнопки
    └── окно книги              http://127.0.0.1:<web_port>

asledgerd
├── web-интерфейс               :8777
└── REST API                    :8778/api/v1
```

Renderer не получает доступ к Node.js: включены `contextIsolation`, `sandbox`
и `nodeIntegration: false`. В renderer доступен только узкий API из
`src/shared/ipc.ts`. Пароли, токены и ключи в `config.json` не хранятся.

## Оформление

В шапке окна управления используется общий `assets/logo/asledger-logo.svg` —
тот же логотип, что в webUI сервера и Android-клиенте. Renderer получает его
через `publicDir` electron-vite, поэтому копии в `desktop/` нет. Иконка
основного окна и окна книги берётся из `assets/logo/icon-512.png`; при
неполной сборке без ассетов Electron использует иконку по умолчанию.

## Установка

### Linux

AppImage:

```bash
chmod +x asledger-<версия>-linux-x86_64.AppImage
./asledger-<версия>-linux-x86_64.AppImage
```

deb (системная установка, обычно нужен root):

```bash
sudo apt install ./asledger-<версия>-linux-amd64.deb
# затем запустите «asledger» из меню приложений
```

Для arm64 используйте `asledger-<версия>-linux-arm64.AppImage` или
`asledger-<версия>-linux-arm64.deb`.

### Windows

1. Скачайте `asledger-<версия>-win-x64.exe` (NSIS) или
   `asledger-<версия>-win-x64-portable.exe`.
2. Запустите файл. NSIS с `perMachine: false` ставится в пользовательский
   каталог и не требует администратора.
3. Если SmartScreen предупреждает о неизвестном издателе, это ожидаемо для
   неподписанного MVP; проверьте SHA-256 из релиза.

ZIP `asledger-<версия>-win-x64.zip` можно распаковать в любой каталог и
запустить `asledger.exe` без установки.

### macOS

В `v1.3.0` macOS не поддерживается: нет подписи и нотаризации. Не используйте
неподписанную сборку как поддерживаемый артефакт.

## Первый запуск

1. Запустите приложение. Оно создаст `config.json` рядом с исполняемым файлом,
   если каталог доступен для записи. Иначе конфиг будет в пользовательском
   каталоге Electron (`app.getPath('userData')`).
2. Если книги ещё нет, придумайте пароль и повторите его в окне «Новый пароль
   книги». Индикатор сложности — подсказка, а не гарантия стойкости. Пароль
   задаёт ключ SQLCipher и создаёт sidecar `data/asledger.db.kdf.json`. Для
   существующей книги введите текущий пароль; для незашифрованной книги сначала
   выполните `asledgerctl migrate-encrypt` (см.
   [docs/security.md](security.md)).
3. Дождитесь статуса «Готово». Это значит, что `asledgerd` запустился и
   healthcheck `http://127.0.0.1:8778/api/v1/health` отвечает.
4. Нажмите «Открыть книгу» — откроется отдельное окно с web-интерфейсом.
5. Пройдите мастер настройки книги: пользователь, шаблонный план счетов или
   импорт, начальные остатки.

Пароль передаётся дочернему `asledgerd` через stdin (`-password-fd=0`), а не
через argv или env. Если включить «Запомнить ключ», при следующем запуске
используется сохранённый 32-байтовый ключ, а не пароль.

Если статус «Ошибка», причина и путь к журналу показаны в карточке сервера.

## Конфигурация и данные

`config.json` в portable-режиме лежит рядом с приложением:

```json
{
  "web_port": 8777,
  "api_port": 8778,
  "data_path": "data",
  "log_path": "logs"
}
```

- `web_port` — web-интерфейс книги, по умолчанию `8777`.
- `api_port` — REST API для Android и healthcheck, по умолчанию `8778`.
- `data_path` — каталог книги; относительный путь считается от `config.json`.
- `log_path` — каталог журналов; относительный путь считается от `config.json`.

Секретов в `config.json` нет. Пароль и производный ключ в него не пишутся.
Рядом с книгой лежит sidecar `data/asledger.db.kdf.json`: соль и параметры
Argon2id, без пароля и результата KDF. Модель угроз и решения по ключу — в
[docs/security.md](security.md).

В разделе «Безопасность» есть чек-лист (общая папка, сложность пароля,
резервная копия) и предупреждение об облачной папке. Книга и sidecar остаются
зашифрованными, но облачная синхронизация может создать конфликт или откатить
файл; облако не заменяет резервную копию.

Если portable-каталог только для чтения, используется `userData`:

- Linux: обычно `~/.config/asledger/`;
- Windows: обычно `%APPDATA%\asledger\`.

Точный путь журнала всегда виден в окне приложения. Книга — файл
`data/asledger.db` (SQLCipher, режим WAL); рядом лежит sidecar
`data/asledger.db.kdf.json`. Перед резервным копированием остановите сервер и
скопируйте каталог `data/` целиком либо используйте `asledgerctl backup`:
команда копирует книгу и sidecar.

## Пароль, ключ и «Запомнить»

- Ключ выводится из пароля через Argon2id в main-процессе Electron; renderer
  пароль не хранит и не получает сохранённый ключ.
- «Запомнить ключ» сохраняет в `safeStorage` только 32-байтовый raw-ключ.
  Пароль в системное хранилище не попадает.
- На Linux используется Secret Service (`gnome_libsecret`, `kwallet`). Если
  Electron выбрал `basic_text` или шифрование недоступно, флажок отключён и
  пароль запрашивается при каждом запуске. Это защита от ложного чувства
  безопасности: `basic_text` не шифрует ключ.
- Кнопка «Забыть сохранённый ключ» удаляет только blob в системном хранилище.
  Пароль и книгу это не удаляет; без пароля нужна резервная копия.
- «Сменить пароль» в окне приложения останавливает `asledgerd`, вызывает
  встроенный `asledgerctl passwd`, создаёт зашифрованную резервную копию
  `<книга>.pre-rekey-*.db` и sidecar, проверяет новую книгу и запускает сервер
  с новым паролем. Если включено «Запомнить», сохранённый ключ заменяется;
  иначе старый ключ удаляется. Путь к резервной копии показывается в разделе
  «Безопасность». На Unix новый пароль передаётся через fd 3, на Windows —
  через временный файл 0600 в `%TEMP%`, который удаляется после запуска.
- После смены пароля через CLI (`asledgerctl passwd`) старый сохранённый ключ
  перестаёт подходить: приложение удалит его при ошибке открытия и попросит
  пароль заново.
- Восстановления забытого пароля нет. Если «Запомнить» не включено, нужна
  резервная копия и старый пароль/ключ.

## Удаление данных

1. Закройте приложение и убедитесь, что процесс `asledgerd` завершён.
2. Удалите `config.json`, каталоги `data/` и `logs/` в portable-каталоге или в
   `userData`.
3. Удалите сохранённый ключ кнопкой «Забыть ключ» или вместе с `userData`.
4. При установке через deb/NSIS удалите приложение штатным способом.

## Подключение Android

1. Компьютер и телефон должны быть в одной локальной сети (обычно Wi-Fi).
2. В разделе «Адреса для телефона» выберите адрес и скопируйте **API URL**
   вида `http://192.168.1.42:8778`.
3. В Android-клиенте укажите этот адрес и порт API.
4. Если телефон не подключается, разрешите входящие соединения на порты
   `8777/tcp` и `8778/tcp` в брандмауэре компьютера.

`127.0.0.1` в списке не показывается: с телефона он указывает на сам телефон.
Сервер слушает все интерфейсы, но приложение не открывает доступ из интернета
и не заменяет настройку сети. Для внешнего доступа нужны отдельные меры
защиты; в MVP его нет.

## Журнал и диагностика

- Журнал: `logs/asledgerd.log`; панель показывает последние 200 строк или
  64 КиБ, файл не загружается целиком.
- «Скопировать логи» копирует текущий хвост, «Открыть файл» открывает журнал
  системным приложением.
- Пароли, токены, `Authorization`/`Bearer` и секретные JSON-поля маскируются
  перед записью и показом.
- Ротации в MVP нет; при необходимости удалите старый журнал при остановленном
  сервере.

Типичные ошибки:

| Сообщение | Что проверить |
| --- | --- |
| `Не найден asledgerd` | Пакет повреждён; переустановите приложение |
| `address already in use` | Порт занят другим процессом; освободите его или измените `web_port`/`api_port` |
| `Сервер не ответил` | Журнал, права на `data/` и `logs/`, свободное место |
| `Сервер завершился` | Причина в журнале; проверьте порты и целостность книги |

Проверка версии и healthcheck:

```bash
asledgerd --version
curl -fsS http://127.0.0.1:8778/api/v1/health
```

## Ограничения MVP

- Нет автообновления, автозапуска, системного трея и нескольких книг.
- Нет удалённого доступа, HTTPS, QR-кода и ограничения по подсетям
  (`allowed_subnets` не поддерживается).
- Нет встроенного редактора конфигурации и управления пользователями.
- Windows-артефакты не подписаны; macOS исключён из `v1.3.0`.
- CLI `asledgerctl passwd` не обновляет `safeStorage`; смена пароля из окна
  приложения обновляет сохранённый ключ сама. После CLI-смены при следующем
  запуске приложение попросит новый пароль.

## Сборка

Инструкции для разработчика, версии и упаковка — в
[desktop/README.md](../desktop/README.md). Проверки CI:

```bash
cd desktop
npm ci
npm run check
npm run build:backend
xvfb-run -a npm run test:e2e   # Linux без графического сеанса
npm run package:dist
npm run verify:package
```

`npm run build:backend` собирает два бинаря для каждой цели: `asledgerd` и
`asledgerctl`. Оба попадают в `resources/bin` упакованного приложения;
`asledgerctl` нужен для смены пароля из UI.
